01

Define the problem

A binary decision-support prototype

The task is supervised binary classification: estimate the probability that an application receives approval (1) rather than rejection (0). The useful output is a ranked probability plus a review threshold—not an unexplained yes/no.

Business value

Consistent triage could prioritise clear cases and route uncertain applications to a trained reviewer, reducing handling time while preserving human oversight.

Critical boundary

The label is an approval decision, not repayment or default. This experiment learns the supplied policy pattern; it does not prove creditworthiness or responsible-lending compliance.

Choose the approach

One pipeline, three serious candidates

A dummy classifier anchors the comparison. Logistic regression tests a transparent linear boundary; random forest tests bagged nonlinear trees; histogram gradient boosting tests sequential nonlinear corrections.

Missing values

None were observed. Median and most-frequent imputers remain inside the pipeline so future incomplete rows fail gracefully.

Feature selection

All relevant fields were retained except gender. Gender never reaches the model and is used only to inspect subgroup outcomes.

Outliers

Age and employment contain implausible maxima. Learned winsorisation limits their influence and avoids fitting bounds on validation or test data.

Leakage control

Every learned transform is inside a scikit-learn Pipeline. The split happens first; fitting happens only on the appropriate training fold.

Partition rationale

70% gives the models 31,500 examples; 15% supports unbiased model and threshold choices; 15% leaves 6,750 untouched cases for one final estimate. A fixed seed makes the experiment repeatable.

What drives predictions?

Permutation importance measures the drop in test average precision when one raw feature is shuffled. It is model-specific association, not causality.

Governance & limitations

Good prototype, insufficient evidence for lending

Do not deploy this model for autonomous credit decisions.

The study validates technical discrimination on synthetic data; it does not validate lawfulness, real-world outcomes, stability, explainability obligations, or consumer impact.

Subgroup diagnostic

Gender was excluded from the model and used only here. Similar rates in this synthetic test split do not prove fairness; proxy variables, label bias, intersectional groups, and real-world drift remain untested.

Recommended next gates

  1. 01
    Replace the target

    Train against a defined repayment or loss outcome rather than reproducing approvals.

  2. 02
    Validate prospectively

    Use temporal and out-of-population holdouts; monitor drift and calibration.

  3. 03
    Set explicit costs

    Choose thresholds from documented false-approval and false-rejection impacts.

  4. 04
    Run formal fairness review

    Assess protected and intersectional groups with legal, risk, and domain stakeholders.
